# Headless Commerce — Angular 22 storefront + NestJS 12 API

Portfolio project. Two independently deployable apps in one repo:

| Path | What | Stack | Deploy |
| --- | --- | --- | --- |
| `api/` | JSON API: catalog, cart, checkout, payments (Pix), webhooks, auth | Node 24 · NestJS 12 (ESM) · Drizzle ORM 0.45 · PostgreSQL 17 · class-validator · Swagger · Vitest 5 (e2e on PGlite) · oxlint · Prettier | Fly.io (Dockerfile/fly.toml) or Railway/Render |
| `storefront/` | SSR storefront | Node 24 · Angular 22.2 (zoneless, signals, `httpResource`, Signal Forms) · Angular Material 22 · Tailwind 4 · NgRx SignalStore (prompt 02) · Vitest · angular-eslint | Vercel (root dir `storefront`, SSR via `api/index.mjs`) |
| infra | PostgreSQL 17 (local) → **Supabase Postgres** in prod; Meilisearch; Redis; Mailpit | `docker-compose.yml` | — |

The API is the only thing that talks to the database. The storefront consumes `/api/v1/*` through `storefront/src/app/core/api/*`. The HTTP contract lives in `api/docs/api.md` and `storefront/src/app/core/api/types.ts` — **update both in the same change** whenever a resource changes.

## Commands

```bash
docker compose up -d                                   # postgres, meilisearch, redis, mailpit
cd api && npm run setup && npm run start:dev           # http://localhost:8000/api/v1  (docs: /api/docs)
cd storefront && npm install && npm start              # http://localhost:4200
```

Quality gates (run before saying a task is done):

```bash
cd api && npm run lint && npm run typecheck && npm test && npm run test:e2e
cd storefront && npm run lint:fix && npm run typecheck && npm test && npm run build
```

`npm run test:e2e` in the API boots the real app on PGlite (in-memory Postgres) — no Docker needed, use it liberally.

## Working agreement

- Read `PROMPTS.md` to see which step we're on. Each prompt is one vertical slice: schema → service → controller/DTO → tests → storefront feature → docs.
- Finish a slice completely (tests green, docs updated) before starting the next. No "TODO later" in shipped code.
- Prefer idiomatic Nest/Angular conventions over clever abstractions. Reviewers will be Angular/Node people.
- Commit per slice with a conventional message (`feat(api): …`, `feat(storefront): …`). Do not push unless asked.
- Never edit `.env` files — edit `.env.example` and tell the user what to set.
- Secrets never go in code, fixtures, or docs. Config is read only through `ConfigService<Env>` (`api/src/config/env.ts`).

## Non-negotiable invariants

- Money is **integer cents** end to end. No floats, no `numeric` columns, no `number * 0.1`.
- Stock: `0 <= inventory.reserved <= inventory.quantity` — enforced by a DB CHECK and by `SELECT … FOR UPDATE` (`.for('update')`) inside `db.transaction()` when reserving.
- `POST /checkout` is idempotent on the `Idempotency-Key` header; the same key returns the same order.
- Every inbound webhook is persisted in `webhook_events` (unique `provider + external_id`) **before** any side effect; redeliveries are no-ops.
- Order status changes go through `transitionOrder()` (`api/src/orders/order-status.ts`). Never write `status` directly.
- Prices in cart items and order items are **snapshots**; always re-validate against the live product at checkout.
- Schema changes go in `api/src/database/schema.ts` → `npm run db:generate` → commit the SQL in `api/drizzle/`. Never hand-edit a generated migration that has been applied.

Per-area conventions are in `.claude/rules/` (loaded automatically when you touch those paths). `storefront/CLAUDE.md` is the Angular team's official best-practices file generated by `ng new --ai-config claude-code`; it applies to everything under `storefront/`.
